# 🧠 The AI-Assisted Git Cheat Sheet

A quick reference guide for managing code generated by AI coding tools. 

## 0. The Final Push to Vercel
Use these steps to save and push to github which vercel will auto update

| `git add .` | Stages all modified files. |
| `git commit -m "..."` | Saves the staged files as a checkpoint - be sure to add note in quotes |
| `git push origin main` | Pushes the checkpoint to github |

## 1. The Daily Loop (Save Your Progress)
Use these commands constantly—ideally after every 2-3 successful AI prompts.

| Command | What it does | When to use it |
| :--- | :--- | :--- |
| `git status` | Shows which files have changed. | **Step 1:** Run before anything else to see what the AI actually touched. |
| `git add .` | Stages *all* modified files. | The AI's code works and you are ready to "save" the project state. |
| `git add <filename>` | Stages only a specific file. | The AI changed 5 files, but you only want to save 1 of them. |
| `git commit -m "..."` | Saves the staged files as a checkpoint. | **Step 2:** Write a quick message (see Prefixes below). |

## 2. The "Undo" Buttons (For AI Hallucinations)
If the AI writes code that breaks the app, use these to time-travel back to safety.

| Command | What it does | When to use it |
| :--- | :--- | :--- |
| `git restore .` | Throws away all current unstaged changes. | **The Panic Button.** The AI ruined your files and you haven't committed yet. |
| `git reset --soft HEAD~1`| Undoes the last commit, keeps code changes. | You made a typo in your commit message. |
| `git reset --hard HEAD~1`| **Warning:** Deletes commit AND code changes. | The AI's last *committed* code is garbage, and you want it erased. |

## 3. Branching (For Big Experiments)
Do massive refactors in a sandbox so the AI doesn't break your main code.

| Command | What it does | When to use it |
| :--- | :--- | :--- |
| `git checkout -b <name>`| Creates a new branch and switches to it. | Before asking the AI to attempt a risky refactor. |
| `git switch main` | Switches back to your main codebase. | You are done experimenting and want your stable code back. |
| `git merge <name>` | Merges the branch into your current code. | The AI experiment was a success, keep the new feature. |

## 4. Backup and History
| Command | What it does | When to use it |
| :--- | :--- | :--- |
| `git log --oneline` | Shows a condensed list of commit history. | To look up a previous checkpoint ID or see yesterday's work. |
| `git push` | Uploads your commits to the cloud. | End of the day, to back up your work to GitHub/GitLab. |

## 📝 Bonus: Standard Commit Prefixes
Keep your project history organized by starting your commit messages with these prefixes:

* `feat:` A new feature (e.g., `feat: add user authentication`)
* `fix:` A bug fix (e.g., `fix: resolve data mapping issue`)
* `refactor:` Code change that neither fixes a bug nor adds a feature (e.g., `refactor: clean up navbar component`)
* `style:` UI/CSS changes (e.g., `style: update button hover state`)
* `chore:` Maintenance tasks (e.g., `chore: update dependencies`)
